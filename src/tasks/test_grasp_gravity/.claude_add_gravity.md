# Gravity Compensation Assist

## Summary

Added a per-step external force on the object that exactly opposes the curriculum gravity and decays to zero as fingertip contact strength increases. This allows the `gravity_adr` curriculum to ramp gravity from 0 → 9.81 m/s² while the robot learns: at episode start the object "floats," and the assist retreats as the robot grips it.

### `mdps.py`

Added `apply_gravity_compensation_assist` (after `_contact_sensor_max_magnitude`):

```python
def apply_gravity_compensation_assist(
    env, env_ids,
    asset_cfg, contact_sensor_names,
    low_contact_force_threshold=0.25,
    high_contact_force_threshold=4.0,
)
```

**Logic:**
- Reads current physics gravity live from PhysX (`SimulationContext.instance().physics_sim_view.get_gravity()`), so it is always in sync with whatever `variable_gravity` just applied.
- Reads actual per-env object mass from `object.root_physx_view.get_masses()` (reflects the 0.4–1.6× startup scaling; using default_mass would cause light objects to float upward).
- Computes total contact strength = sum of per-finger max contact magnitudes using the existing `_contact_sensor_max_magnitude` helper.
- Computes `assist_scale` via linear interpolation: 1 when contact < `low_threshold`, 0 when contact ≥ `high_threshold`.
- Applies `F = −gravity × mass × assist_scale` in world frame via `object.set_external_force_and_torque(..., is_global=True)`.

Reuses existing helpers: `_normalize_env_ids` (line 849) and `_contact_sensor_max_magnitude` (line 865).

## Execution order (each policy step)

1. **Reset** (`_reset_idx`):
   - `curriculum_manager.compute` → `gravity_adr` updates `variable_gravity.params`
   - `scene.reset(env_ids)` → clears external wrench buffers for reset envs
   - `reset_gravity` (reset event) → sets PhysX gravity to `[0,0,0]` as safe baseline

2. **Interval events** (`event_manager.apply(mode="interval")`):
   - `variable_gravity` → sets PhysX gravity to curriculum value
   - `gravity_compensation_assist` → reads live gravity, writes compensation wrench

3. **Next physics substep** → `scene.write_data_to_sim()` pushes wrench to PhysX

---

## Key design decisions

| Decision | Reason |
|---|---|
| Read gravity from live PhysX | Avoids coupling to event-param address; correct regardless of curriculum state |
| `root_physx_view.get_masses()` | Actual per-env mass after startup scaling; nominal default_mass would over/under-compensate |
| `LeapEventCfg` subclass | Contact sensors only exist in `LeapObjectEnvCfg`; keeps base `EventCfg` unmodified |
| `is_global_time=True` on `variable_gravity` | Gravity is a global PhysX param; env_ids are irrelevant |
| `is_global_time=False` on assist | Per-env forces require a proper env_ids tensor |
